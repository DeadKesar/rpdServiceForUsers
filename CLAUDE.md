# CLAUDE.md — прототип АС создания РПД и ФОС

## О проекте

Прототип к магистерской ВКР (МГТУ «СТАНКИН», Порядин В. С.): «Исследование процесса создания методических документов и разработка автоматизированной системы формирования рабочих программ дисциплин и фондов оценочных средств».

Код — часть научной работы: решения должны соответствовать проекту из главы 2 (`docs/design/`). Если задание расходится с проектом или проект неоднозначен — остановись и спроси, не додумывай.

Текущее задание этапа — в `docs/tasks/`. Выполняй только его; идеи за пределами задания записывай в `docs/tasks/ideas.md`.

## Стек

- .NET 10 (версия SDK — в `global.json`), ASP.NET Core, Carter — вертикальные срезы.
- EF Core 10 + PostgreSQL 17 (Npgsql, EFCore.NamingConventions → snake_case).
- ASP.NET Core Identity + OpenIddict 7: сервер авторизации внутри хоста API, поток authorization code + PKCE.
- Blazor WebAssembly — клиент, его раздаёт хост API (один адрес, CORS не нужен).
- xUnit; с этапа 2 — Hangfire и Testcontainers.
- Позже: генерация DOCX (Open XML SDK) и PDF (LibreOffice) — этап 5.

**Отличие реализации от `docs/design/`:** в документах сервер аутентификации — Duende IdentityServer в отдельном контейнере. Реализовано иначе: OpenIddict внутри хоста API (лицензионные причины). Ориентируйся на реализацию.

## Структура

- `src/RpdFos.Core` — прикладное ядро: сущности, `AppDbContext`, миграции, сквозные механизмы (`VersioningInterceptor`). Общее для API и фоновых задач.
- `src/RpdFos.Api` — хост: модули Carter (`Features/<Область>/<Область>Module.cs`), конечные точки OIDC (`Features/Auth`), страница входа (Razor Pages), `Infrastructure` (AuthSeed, Policies, ConcurrencyExceptionHandler).
- `src/RpdFos.Web` — Blazor WASM, клиент OIDC `rpdfos-web`. Отдельно не запускается.
- `tests/` — тесты.
- `docs/design` — проект (глава 2 ВКР), `docs/tasks` — задания этапов, `docs/runbooks` — пошаговые инструкции этапов, `docs/journal.md` — журнал разработки для главы 4.

## Команды

```
docker compose up -d db                       # база
dotnet run --project src/RpdFos.Api           # https://localhost:5081, Development: автомиграции и засев
dotnet build                                  # без ошибок и предупреждений
dotnet test
dotnet ef migrations add <Имя> -p src/RpdFos.Core -s src/RpdFos.Api
```

Первый администратор — user-secrets проекта `RpdFos.Api`: `Seed:AdminEmail`, `Seed:AdminPassword`.

## Соглашения

- **Срезы.** Новая функциональность — новый модуль Carter в `Features/<Область>`. Правила домена (переходы статусов, валидация) — в Core, не в эндпоинтах.
- **Схема БД** меняется только новыми миграциями; существующие не правятся. Сгенерированную миграцию прочитать перед применением.
- **Имена.** Свои таблицы и колонки — snake_case (через конвенцию). Таблицы Identity и OpenIddict остаются с именами библиотек (`AspNetUsers`, `OpenIddict*`) — не переименовывать.
- **Оптимистичная блокировка.** Сущности с версией реализуют `IVersioned`. Версию увеличивает `VersioningInterceptor`. В эндпоинтах версию не трогать — только подставлять версию клиента в `OriginalValue`.
- **Ошибки** — ProblemDetails: 404 не найдено, 409 конфликт состояния или версии, 422 неверные данные, 401/403 доступ. Конфликт версий превращает в 409 `ConcurrencyExceptionHandler` — без `try/catch` в эндпоинтах.
- **Доступ.** Эндпоинты API по умолчанию требуют токен. Роли: `teacher`, `methodist`, `approver`, `admin`; политики — `Infrastructure/Policies.cs`. Не ослаблять политики ради тестов: в тестах подменяется аутентификация, а не правила.
- **Учётная запись ≠ сотрудник.** `AppUser` (Identity) — только для входа. Справочник сотрудников (`users`) содержит и людей без входа — подписантов. Связь — через `identity_subject`.
- **Удаление мягкое:** статус `deleted` и флаг `IsDeleted` выставляются вместе, одним методом сущности.
- **Язык.** Интерфейс — на русском. Комментарии в коде — на русском, кратко, объясняют «почему».
- **Пакеты** — только бесплатные для вуза (MIT, Apache 2.0, BSD, LGPL). Без предупреждений NuGetAudit. Уязвимая транзитивная зависимость лечится явной ссылкой на исправленную версию с комментарием «зачем».
- **Секреты** не коммитить: пароли — user-secrets или переменные окружения.
- **Персональные данные** не коммитить: ФИО реальных сотрудников в фикстурах тестов — только обезличенные.

## Git

Ветка `main`. Коммиты мелкие, в стиле Conventional Commits: `feat:`, `fix:`, `chore:`, `test:`, `docs:`, `refactor:`. Перед коммитом `dotnet build` и `dotnet test` — зелёные. После каждого коммита — `git push` (разрешено автором; отдельного подтверждения не нужно). Веха этапа — аннотированный тег: `git tag -a v0.N -m "…"`, push вместе с тегами (`git push --follow-tags`).

Задания этапов (`docs/tasks/etap-*.md`) — внутренняя документация автора: в репозиторий их не добавлять, в том числе принудительно (`git add -f`). Уже закоммиченные `etap-2.md` и `etap-3.md` не трогать.

## Чего не делать

- Не удалять `src/RpdFos.Api/Properties/launchSettings.json`: профиль `https` в окружении Development нужен для входа. OpenIddict принимает только HTTPS, а адрес возврата клиента — `https://localhost:5081`.
- Не запускать клиент отдельно от хоста API.
- Не добавлять функциональность за пределами задания этапа.

## Контекст ВКР — кратко

- **Роли:** Преподаватель, Методист, Утверждающий, Администратор.
- **Шаблон:** 6 статусов (`empty`, `draft`, `saved_draft`, `published`, `archived`, `deleted`).
- **Документ:** 9 статусов (`draft`, `saved_draft`, `under_review`, `returned`, `accepted`, `approval`, `approved`, `archived`, `deleted`) и флаг `is_outdated`.
- **Согласование** — параллельное электронное.
- **Хранение** — гибридная модель: нормализованные критичные поля + содержимое документа в `payload jsonb`, структура задаётся JSON Schema типа документа.
- **Исходные данные:** учебный план (`.xlsx`), список компетенций (`.docx`), матрица компетенций (`.docx`), должности сотрудников (`.xlsx`).
