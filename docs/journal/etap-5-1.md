**6. Правка методистом полей из учебного плана.**

- Кто и где — правило ядра `DocumentTransitions.EditScope`:

  - автор — своё содержимое без полей плана;

  - Поля, закрытые статусом (`x-readonly-after`), остаются закрытыми.
- Поля плана — поддеревья с `readOnly` в схеме (`PlanFields.Paths`). Значение по плану — то, что дало бы предзаполнение сейчас. Отличия считаются по листьям: «лекции 1 семестра», а не трудоёмкость целиком.

- *Проверка:* предупреждение «Значение отличается от учебного плана: в плане …» у каждого исправленного листа. Отправку и приём оно не блокирует.

- *Печать* — по часам документа, без пометок: таблица трудоёмкости, разделы дисциплины и строки аттестации берут семестры из содержимого. «Часов по плану» (`AutofillByPlan`) печатается из поля документа вместо источника плана.

  - поле плана открыто исправляющему, остальное — по статусу;
  - исправленное поле помечено «изменено методистом, в плане: …», в подсказке — кто и когда;

## Доработки по проверке в браузере — веха `v0.6.2` (25.10.2026)

**1. Виды СРС в значениях по умолчанию.** На странице шаблона у «самостоятельного изучения разделов» нет выбора разделов и подписи о тематическом плане: разделы выбираются в документе, у шаблона тематического плана нет (признак контекста формы `IsTemplate`). Пустой список разделов у вида по умолчанию остаётся признаком, что автор выбирает разделы. На неопубликованной редакции список видов редактируется целиком — название, обозначение, добавить, удалить; подсказок из умолчаний в шаблоне нет — список и есть умолчания. Подписи «Разделы:», «Индикаторы:», «Из видов самостоятельной работы:», «Замечание:» получили отступ: Blazor убирает пробелы между элементами разметки, и текст склеивался («Разделы:появятся…»).

**2. Несохранённые значения по умолчанию на странице шаблона.** «Сохранить» и «Опубликовать» перестраивали форму умолчаний из ответа сервера и стирали несохранённые правки. Теперь эти кнопки сначала сохраняют умолчания (с ошибками — останавливаются и показывают места), остальные действия (загрузка оформления) несохранённые правки в форме не трогают. Правка отмечается по вводу (`oninput`), страница перерисовывается при первой — как в редакторе документа: кнопка сохранения, подсказка у кнопок и подтверждение ухода со страницы (`NavigationLock`, в том числе закрытие вкладки) знают о ней сразу. После подтверждённого удаления шаблона второй вопрос не задаётся.

**3. Вёрстка длинных значений.** Длинная строка без пробелов (адрес, код) раздвигала страницу. В `app.css`: `overflow-wrap: anywhere` для всего содержимого страницы (наследуется — поля, подписи, таблицы, сообщения, пометки полей; у пометок снят `nowrap` Bootstrap), `min-width: 0` у элементов flex и grid (колонки Bootstrap, `d-flex`, группы полей, карточки) — иначе они не уже содержимого. Широкие числовые таблицы (трудоёмкость, виды СРС) прокручиваются внутри себя.
- Многострочные поля с высотой по содержимому (`textarea.auto-grow`: CSS `field-sizing: content`, для браузеров без него — высота по прокрутке при вводе и при появлении поля): пункты списков строк (задачи, ПО, материально-техническое обеспечение, периодика) и длинные поля записей. В таблице записей длинные поля — отдельной строкой во всю ширину над короткими столбцами; длинное поле — подсказка схемы `x-ui-widget: textarea` (библиографическая запись, название интернет-ресурса, тема занятия), в шаблонах до неё — строка с `minLength` от 20 (библиографическая запись).
- Перевод строки в таком поле при уходе из него становится пробелом: значение — один абзац, в печати перевод разорвал бы пункт списка.
- *Найдено при проверке в браузере:* на ширине 400 px таблицу закладок на странице шаблона раздвигали имена закладок в `<code>` — Bootstrap задаёт `code` `word-wrap: break-word`, он перекрывает унаследованное `anywhere`; правило для `main code` — отдельным коммитом.

**4. Раздел 2.1 у дисциплины без предшественников.** У дисциплины 1 семестра выбирать пререквизиты не из чего, и после фразы «…при освоении следующих дисциплин ОП ВО:» в печати была пустота. Теперь — формулировка по уровню образования направления: магистратура — «результаты обучения, полученные при освоении программы бакалавриата или специалитета», бакалавриат и специалитет — «…среднего общего образования».
- Текст — в данных сопоставления (`noCandidates` у закладки `AutofillRequirementsLast`: код уровня → текст), правило — в ядре (`DisciplineFacts.NoCandidatesText`): поле выбора из плана пусто и кандидатов в плане нет. Выбранное есть (план переимпортирован, ссылки остались) — печатается выбранное.
- Редактор показывает ту же формулировку подсказкой («В печатной форме вместо списка: …»): метаданные документа берут её из сопоставления его шаблона (`noCandidatesTexts`).
- Сопоставление — снимок в шаблоне: формулировка есть у шаблонов, оформление которых загружено после этой правки (загрузить оформление заново — сопоставление по умолчанию пересоздаётся).

**5. Должность составителя.** Должность из справочника сотрудников подставляется при добавлении составителя (и у автора — при создании документа) и правится в таблице как обычное поле. Если в справочнике её нет, поле пустое с подсказкой «нет в справочнике — введите должность»; должность стала обязательной к отправке (`required` у составителя схемы новых шаблонов): раньше пустая должность молча печаталась бланком.

**6. Исправление поля из плана — без перезагрузки.** Ответ сохранения раздела (`SectionSaved`) несёт состояние всех разделов (правка трудоёмкости меняет заполненность тематического плана) и, если правил исправляющий, историю исправлений. Исправление поля из плана методистом или администратором сохраняется сразу после ухода из поля (`SchemaContext.PlanFieldChanged`; пришло во время другого сохранения — следом за ним), а при наборе в таком поле форма перерисовывается — пометка «изменено методистом, в плане: …» видна сразу. Предупреждение «значение отличается от учебного плана», ошибки зависимых разделов и список исправлений обновляются тем же ответом.
