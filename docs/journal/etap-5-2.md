## Этап 5.2. Доработки перед согласованием — веха `v0.6.3` (05.11.2026)

**A1. Скачивание файла оформления.** На странице шаблона рядом с именем DOCX-оформления — «Скачать» (методист и администратор, любой статус шаблона): `GET /api/templates/{id}/print-template` отдаёт исходный файл с исходным именем, файла нет — 404 «Шаблон оформления не загружен».

**A2. Учебный год в имени файла печати.** *Отступление от FR-GEN-03* («<Тип>_<Дисциплина>_<Год>»): имя — «РПД_<дисциплина>_<ГГГГ-ГГГГ>.docx», учебный год — из титула документа (`/title_page/academic_year`, «2026/2027» → «2026-2027»). По одному году не отличить РПД одной дисциплины для разных наборов. Учебного года нет или он не в формате — год документа, как раньше. Так же для PDF и ФОС (правило общее, `DocumentPrinting.Period`).

**B1. Состав разделов по данным документа и правка видов аттестации.**
- *Отступление от FR-TPL-14:* условные разделы (`x-visible-if`) — по трудоёмкости документа (`DocumentSemesters.Of`), а не по учебному плану: 3.3 и 4.4 — по лабораторным, 3.4 и 4.5 — по практическим, 3.5 — по курсовому проекту или работе. Так везде: метаданные редактора, сохранение раздела, полная проверка, печать (скрытые места и источники `parser.discipline.semesters`, `course`, `attestation`, `course_work_kind`, `academic_year` в `PrintContext`). Имена источников в схеме прежние; пока исправлений нет, результат тот же.
- Вид курсового проектирования (`course_work.kind`) следует за видами аттестации документа: исправление добавило курсовой проект — вид ставится сам (раздел появляется с одним видом и без тем), изменение пишется в `audit_log` как исправление поля плана. Курсового проектирования не осталось — раздел скрыт, но остаётся в документе как есть: не проверяется, в печати — заглушка.
- *Дополнение условия приёма UC-07:* принять можно только документ без ошибок полной проверки (вдобавок к «нет неразрешённых замечаний»), иначе 422 «Документ не прошёл проверку» с перечнем, как при отправке.
- *Отступление от этапа 5.1* («статус от исправления не меняется»): исправление принятого документа, после которого полная проверка находит ошибки, возвращает его автору. Без подтверждения — 409 «Исправление вернёт документ автору» с перечнем причин (`confirmReturn` в ответе); с подтверждением (`confirmReturn` в запросе сохранения раздела) — статус «На доработке», по замечанию от исправившего на раздел (место — первая ошибка раздела, текст — ошибки раздела), в истории — «возвращён после исправления данных плана», снимок версии `status_change`. Переход «Принят → На доработке» — правило ядра `DocumentTransitions.CanReturnAfterPlanCorrection`, только по исправлению. Исправление без ошибок оставляет документ принятым. Проверяются все ошибки документа, а не только вызванные исправлением: принятый документ ошибок не имел.
- Предупреждение «Значение отличается от учебного плана: в плане …» и пометка у поля называют виды аттестации по-русски («в плане Экзамен», а не `exam`) — по `x-enum-titles` поля.
- *Клиент:* у исправляющего в трудоёмкости виды аттестации — флажки пяти видов по семестрам, пометка и сохранение сразу после изменения — как у часов; подпись «Виды аттестации меняются в учебном плане» убрана. Ответ 409 с `confirmReturn` редактор показывает перечнем причин и спрашивает «Вернуть документ автору на доработку?»; отказ перечитывает документ — значение возвращается к прежнему, согласие отправляет раздел с подтверждением и перечитывает документ в новом статусе.

**B1.1. Доработки по проверке B1 в браузере (31.10.2026).**

Руками его не правит никто (на сервере поле закрыто как `readOnly`, в редакторе — только для чтения). Запись в `audit_log` при смене вида остаётся.

Без этого следующее сохранение вернуло бы прежние значения, а раздел курсового проекта без вида не сохранился бы.
- Найдено при проверке B1 в браузере (исправлено отдельным коммитом): раздел, появившийся после исправления трудоёмкости, был без полей до перезагрузки — ответ сохранения теперь несёт и скрытые места (`SectionSaved.HiddenPaths`).
- Правило `hours_match_curriculum` (имя каталога было, правило пропускалось) — **предупреждение**: в каждом семестре контактная работа + контроль + самостоятельная работа = з. е. × 36, место — строка семестра. Не ошибка: эти часы правит только методист, а ошибка вернула бы документ автору, который исправить их не может.

**B2. Семестр у раздела дисциплины.**
- *Схема РПД* (новые шаблоны): у темы тематического плана — `semester` (целое, обязательное). Шаблоны, созданные раньше, хранят прежний снимок схемы — их документы работают как раньше.
- *Правило `topic_hours_match_total`*: если у тем есть семестр — сверка по каждому семестру трудоёмкости документа («2 семестр: Лекции: по темам … ч, по распределению часов … ч»), тема в семестре, которого у дисциплины нет, — ошибка у её поля семестра; если семестра нет ни у одной темы (прежние шаблоны) — общей суммой, как раньше. Тема без семестра при семестрах у остальных — ошибка схемы (поле обязательно), в суммы не входит.
- *Редактор:* семестр темы выбирается из семестров трудоёмкости документа; у дисциплины одного семестра он ставится сам и не показывается (так же — у тем, добавленных раньше). Новая тема получает семестр предыдущей. Часы вида занятий, которого в семестре темы нет по распределению, недоступны и показываются «–»; при смене семестра такие часы снимаются. Сводка — по семестрам: вид занятий, «по темам / по распределению часов».
- *Печать «Разделов дисциплины»* — по образцу РПД вуза: темы по семестрам документа в порядке семестров, номер семестра — в ячейке «Семестр», объединённой по вертикали на темы и строку аттестации группы; после тем семестра — «Промежуточная аттестация» (суммы лекций, лабораторных и практических, «СР/контроль» — самостоятельная работа тем / контроль семестра, виды аттестации — только экзамен и зачёты); в конце — «Итого (час.)» с суммами и «СР/контроль» за все семестры. Вида занятий, которого в семестре нет по распределению часов, — «-», как в образце; нет ни в одном семестре — «-» и в «Итого» (найдено при проверке печати ФТД.В.01). Столбец «Неделя семестра» шаблона оформления остаётся пустым. У дисциплины одного семестра — та же схема с одной группой: строки «Итого» и «Промежуточный контроль» этапа 5.1 заменены. Темы без семестра у дисциплины нескольких семестров (прежние шаблоны) — одной группой без номера.
- Подпись «Разделы дисциплины, изучаемые в … семестре» (источник `parser.discipline.semesters`): семестры документа подряд — диапазоном «2-3», иначе через запятую («1, 3», «1-2, 4»).
- *Расхождение задания с данными:* Б1.О.14 «Проектная деятельность» в плане 09.04.04 — модуль (часы — сумма Б1.О.14.01 во 2-м семестре и Б1.О.14.02 в 3-м), а РПД по модулям не создаются с этапа 4. Дисциплин на несколько семестров в плане две — факультативы ФТД.В.01 и ФТД.В.02 (1 и 2 семестр, зачёты). Печать с часами Б1.О.14 (две группы, экзамен и зачёт) проверена модульным тестом без базы (`PartitionPrintingTests`), сквозная — на Б1.О.10.

**B4. Цветовая индикация в редакторе.**
- *Палитра* — переменные CSS в `app.css`: `--rf-ok` (46, 125, 50), `--rf-partial` (249, 168, 37), `--rf-error` (198, 40, 40), `--rf-none` (158, 158, 158). Цвет — не единственный признак: рядом число, текст или подпись.
- *Навигация по разделам:* круг 12 px вместо ✓ / ● N / —, рядом — число недостающего, в подсказке — то же словами; легенда под навигацией с цветами.
- *Новое состояние `SectionFill.Empty` («ни одного»)* и как оно считается (`SectionFill.Required`, `SectionFill.Of`): обязательные элементы раздела — сам раздел-список, если он обязателен в корне схемы или условный (предусмотрен — нужна хотя бы одна запись), либо обязательные поля (`required`) раздела-объекта, если объект обязателен или уже начат. Нет ошибок полной проверки — зелёный («выполнены все»), а если обязательных элементов нет вовсе — серый; есть ошибки и ни один элемент не заполнен — красный; иначе — янтарный (в том числе ошибка правила при заполненных элементах). Серый — и у раздела, не предусмотренного учебным планом; подсказка различает эти случаи.
- *Обязательные поля:* поле узнаёт свою ошибку из `Missing` раздела (`SchemaContext.MissingAt`, разделы в контексте обновляются ответом каждого сохранения): красная рамка 2 px и подпись под полем — «Обязательное поле» или текст ошибки проверки. Простые поля — в `ScalarInput` (так и внутри таблиц и виджетов), виджеты, списки и объекты — в `SchemaField` (рамка вокруг виджета, например пустой предусмотренный раздел лабораторных). Не начатый раздел-объект (его нет в содержимом, проверка называет пустым сам раздел) рамкой целиком не обводится — рамку и подпись получают его обязательные поля (найдено при проверке в браузере: рамка вокруг всех «Целей и задач»). Список недостающего над разделом остался — в нём и ошибки правил.
- *Суммы часов* (`HoursSum`): совпадает — зелёным, нет — красным с подписью «по плану: M» — сводка тематического плана по семестрам, виды СРС, «Итого» в 3.3 и 3.4. Жёлтая подсветка сумм `table-warning` убрана; пометка исправления методиста в трудоёмкости и предупреждения правил — как раньше.
- *Найдено при проверке B4 в браузере:* раздел «Распределение часов» после исправления видов СРС становился серым («обязательного нет»): в схеме у него нет `required`, а требование — правило сверки. Правило проверки на разделе или его полях теперь тоже обязательный элемент (`SectionFill.Required`): исправленный раздел — зелёный, с ошибкой правила при начатом разделе — янтарный.

**B4.1. Рамки и индикаторы — сразу при уходе из поля.**
- *Проверка раздела без сохранения* — `POST /api/documents/{id}/sections/{section}/check`, права — как у сохранения раздела. Тот же путь, что у сохранения (санитизация, поля плана, производные поля, проверка черновика), затем состояние всех разделов по присланному содержимому (`SectionChecked`: разделы, скрытые места, ошибки черновика). Документ, версия, снимок, история и журнал аудита не меняются; ошибки черновика (текст вместо числа) — в ответе вместе с разделами.
- *Редактор:* завершённая правка поля (уход из поля, флажок, добавить и удалить строку — `SchemaContext.Changed`) запускает проверку (`SectionCheckRequested`); исправление поля из плана по-прежнему сохраняется сразу. Ввод не блокируется; ответ применяется, только если с запроса не было новых правок, новых проверок и смены раздела. Сохранение — как раньше (автосохранение, уход из раздела, «Сохранить»): сохранять при каждом уходе из поля нельзя — каждое сохранение пишет снимок версии.

**B5. Справочник сотрудников — страница администратора; учётные записи.**
- *Отступление от FR-TPL-02 и FR-TPL-12:* справочник должностей ведётся в системе на странице администратора «Справочник сотрудников» (S-51 «Справочники»), данные — в таблице `users`; файл должностей — необязательная начальная загрузка, только у администратора. «Импорт данных» (методист и администратор) — комплект из трёх файлов: учебный план, список и матрица компетенций.
- *Правила — в ядре, общие для страницы и загрузки файла:* `EmployeeDirectory` (официальное название уникально среди активных записей; одно место подписанта на кафедру и на институт — `SeatOf`; категория согласована с оргструктурой, как `ck_users_signatory_scope`: заведующий — с кафедрой, директор — с институтом без кафедры, подписанты уровня университета — без подразделения; смена человека на должности — `Vacate`: прежняя запись без учётной записи неактивна, с учётной записью остаётся активной без места). Загрузка файла — `EmployeeImport`: правила этапа 2 вынесены из конвейера импорта без изменений (добавить и обновить по официальному названию, смена человека, записи, которых нет в файле, не трогаются, кафедры — только из справочника кафедр плана); полный импорт пользуется тем же классом — для прежних запусков с файлом должностей.
- *Страница:* таблица записей («Фамилия И. О.», подпись в документах, должность, официальное название, кафедра или институт, категория подписанта по-русски, учётная запись, «активна»), фильтры (фамилия, категория, неактивные), добавить и изменить запись со всеми полями (подпись по умолчанию — из «Фамилия И. О.», `PersonNames`), деактивировать и вернуть (возврат — по тем же правилам места), «Сменить сотрудника на должности» — место (официальное название, должность, категория и её подразделение) переходит к выбранной записи без места или к новой. Конфликт — 409 с текстом («Место подписанта занято: … — «Фамилия»»), неверные данные — 422.
- *Загрузка файла должностей* — кнопка на странице, разбор в фоне (очередь `parsing`), итог — счётчики (добавлено, обновлено, снято с должности) и замечания, строка «Последняя загрузка: файл, когда, записей». *Решение:* запуск хранится в отдельной таблице `directory_imports` (миграция `AddDirectoryImports`, дополнение к модели данных), а не видом запуска в `parser_runs`: там файлы плана и компетенций обязательны, и запуск без плана сломал бы их смысл и ограничения.
- *Журнал аудита:* изменения справочника со страницы — `employee.created`, `employee.updated`, `employee.deactivated`, `employee.reactivated`, `employee.replaced` с `{before, after}`, кто — запись справочника администратора.
- *Учётные записи (FR-ADM-01, страница «Пользователи»):* администратор задаёт новый временный пароль (токен сброса Identity, требования к паролю — как при создании; временная блокировка за неудачные попытки снимается) и отключает или возвращает учётную запись. Отключение — бессрочная блокировка Identity и смена штампа безопасности: войти нельзя (на странице входа — «Учётная запись отключена администратором»), токены не выдаются и не обновляются; себя отключить нельзя. Запись справочника при этом не меняется.

**B6. Ручная привязка строк матрицы к дисциплинам плана.**
- *Библиотека разбора:* строки матрицы с отметками, не найденные в плане по названию или неоднозначные, возвращаются данными (`ExtractionResult.UnmatchedMatrixRows`: название, таблица и строка, семестры, отметки и их компетенции, кандидаты неоднозначной строки), а не только замечанием. Строки без отметок — только замечанием: им нечего терять. Если уточнение по семестрам не оставило ни одного кандидата, кандидатами остаются все совпавшие по названию — из них и выберет методист.
- *Дополнение к модели данных:* таблица `matrix_unmatched_rows` (миграция `AddMatrixUnmatchedRows`) — строки для созданной импортом версии плана: место в файле, семестры, коды, кандидаты, статус (`pending`, `linked`, `ignored`), дисциплина, кто и когда решил, связи матрицы, добавленные привязкой (для отмены).
- *Страница «Импорт данных»* — у запуска, создавшего план, блок «Строки матрицы без дисциплины плана»: название, семестры, коды; выбор — дисциплина этой версии плана (дисциплины, практики, факультативы — без модулей, групп элективов и ГИА; сначала кандидаты, затем дисциплины без связей с матрицей, затем остальные) или «Не учитывать»; «Применить», после — кто, когда и к чему привязал, «Отменить». Доступ — методист и администратор.
- *Правило привязки — в ядре* (`MatrixRowBinding`): связи с компетенциями строки добавляются на уровне компетенций, как при импорте (компетенции версии плана — УК и ОПК ФГОС плана, ПК профиля); кодов, которых нет в списке компетенций, — замечание, связь пропускается; уже существующая связь не дублируется и при отмене остаётся. Отмена удаляет только связи, добавленные этой привязкой. Привязка и отмена — в `audit_log` (`matrix_row.linked`, `matrix_row.unlinked`). Документы, уже созданные по дисциплине, не меняются: правило `competences_match_matrix` покажет расхождение.
- Реальные файлы: строка «Внедрение и эксплуатация информационных систем» (ПК-1, ПК-2) привязывается к элективу Б1.В.ДВ.03.01, и новая РПД по нему предзаполняется этими компетенциями.

**Итог.** Методист и администратор исправляют виды аттестации, а состав разделов, вид курсового проектирования и контактная работа следуют за данными документа; принять документ с ошибками нельзя, исправление после приёма, которое его ломает, после подтверждения возвращает его автору с замечаниями. У тем есть семестр: часы сверяются и печатаются по семестрам, как в образце РПД вуза, таблица 3.1 — тоже по образцу; таблицы 3.3 и 3.4 сверяются с часами. Справочник сотрудников ведёт администратор на своей странице (файл должностей — необязательная начальная загрузка), учётным записям задаётся временный пароль, их можно отключить; строки матрицы без дисциплины плана привязываются вручную.
