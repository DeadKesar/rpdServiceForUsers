## Этап 5.3. Проверка на реальных данных (06.11.2026)

**Задача.** Прогнать систему по корпусу настоящих данных вуза (учебные планы, списки и матрицы компетенций, настоящие РПД) без исправлений системы, собрать отчёты и классифицировать находки. Корпус и отчёты в репозиторий не входят.

**Инструмент `tools/RpdFos.Corpus`** — консольное приложение, не входит в `dotnet test`. Папка корпуса — аргументом или `RPDFOS_CORPUS`, конвертер PDF — `RPDFOS_CONVERTER`; путей в коде нет. База — одноразовая PostgreSQL 17 в контейнере (Testcontainers), миграции и сервисы ядра — те же, что у хоста: `DataExtractor`, `ReferenceImporter`, `DocumentCreation`, `DocumentSubmission.Check`, `DocumentPrinting` (DOCX по шаблону v3 без содержимого автора). Текст настоящих РПД — Open XML SDK (DOCX, копии .doc из преобразованной папки) и PdfPig (PDF, Apache 2.0). Результат — `Сводка.md`, отчёт на каждый план и каждую РПД, `находки.csv` (план или документ; вид; место; сообщение; класс); повторный прогон перезаписывает папку отчётов. Прогон — около 3,5 мин.
- *Классы:* ошибка разбора, пробел модели, ложное срабатывание, данные источника, версия документа, печать, ожидаемо. Класс ставится правилом по тексту замечания; правила уточнялись по прогонам (нули часов при непрочитанной разбивке — ошибка разбора, индикатор без типа — пробел модели без двойного счёта в импорте, пустая кафедра — следствие незагруженной кафедры).
- *Решение:* если разбор не нашёл профиль, инструмент подставляет его из описи комплектов и отмечает это в статусе и сводке — иначе 62 плана из 65 не создавались бы и остальные проверки были бы невозможны. В сравнении с настоящими РПД подставленный профиль не сравнивается.
- *Выбор матрицы* для комплектов без неё — разбор с каждым кандидатом, берётся матрица с наименьшим числом несопоставленных строк; выбор записан в сводку.
- *Сопоставление настоящей РПД с дисциплиной* — по названию в титуле (от «Рабочая программа» до «Уровень» / «Направление»), затем точным названием в имени файла; план — того же направления, ближайшего года. Первые прогоны находили название направления («Информатика и …») и упоминания других дисциплин — окно поиска сужено; однословные названия — только точным совпадением; PDF без кириллицы в тексте пропускаются.

**Итог прогона.** 65 комплектов, планов создано 65 (62 — с подставленным профилем); новых РПД 3363, все напечатаны без сбоя; настоящих РПД 39, сравнено 33 (2 — программы ГИА и практики, пропущены). Находок: ошибка разбора 8295, данные источника 2655, пробел модели 2223, версия документа 117, ожидаемо 1077, печать и ложных срабатываний — 0.

**Главные находки.**
- *Ошибка разбора:* в формате большинства планов название направления и профиль в титуле записаны без кода в той же ячейке — разбор их не находит; почасовая разбивка по семестрам лежит на листах «Курс N», а не на листе «План» — часы по семестрам читаются нулями (отсюда почти все срабатывания `hours_match_curriculum`, нули в таблице 3.1 и расхождения часов с настоящими РПД).
- *Пробел модели:* индикаторы без «Знать / Уметь / Владеть» (одна формулировка действия) не загружаются — около 2100; дисциплины с 0 з. е. и 328 ч (физическая культура, элективные модули) всегда нарушают правило часов; у дисциплины бывает два настоящих документа (обычный и для лиц с ОВЗ), в модели — один.
- *Данные источника:* номера кафедр плана не находятся в справочнике кафедр плана или конфликтуют между планами (в том числе одна кафедра с разным окончанием названия); сотни строк матриц не находятся в планах — новых РПД без компетенций 450.
- Очно-заочная форма, специалитет (до 11 семестров), старые планы после преобразования .xls и модули бакалавриата проходят без сбоев; у специалитета — замечания об аттестации в 10-м семестре без колонок часов.

Исправления системы — после обсуждения находок с автором.
