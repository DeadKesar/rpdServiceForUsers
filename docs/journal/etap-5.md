## Этап 5. Проверка и печать — веха `v0.6` (22.10.2026)

Задание — [etap-5.md](../tasks/etap-5.md).

**После вехи `v0.5`: потеря ввода при уходе со страницы** (нашёл автор при проверке). Признак несохранённых правок ставился по событию `change`, то есть при уходе из поля. Текст, набранный в поле без ухода из него, пропадал без предупреждения при закрытии вкладки или переходе на другой сайт: `NavigationLock` спрашивает подтверждение, только когда признак уже стоит.
- Поля и виджеты обрабатывают `oninput`, форматированный текст — событие `Input` редактора Radzen. Значение сразу пишется в содержимое, признак ставится тут же. Пробелы по краям обрезаются при уходе из поля, как раньше. Недонабранное число («-», «1.») в содержимое не пишется — только отмечается правка, иначе перерисовка стёрла бы набранное.
- Страница перерисовывается при первой правке, а не на каждую клавишу. Автосохранение во время набора сохраняет то, что на экране. Правки, сделанные за время запроса сохранения, признак не снимают: введён счётчик правок.
- *Проверка:* встроенный браузер среды разработки сам разрешает уход со страницы и закрывает вкладки без событий выгрузки, поэтому проверялся обработчик `beforeunload` во время настоящего перехода на другой сайт: при фокусе в поле с набранным текстом он запросил подтверждение. Закрытие вкладки проверил автор в своём браузере — появляется предупреждение о возможной потере данных. Отдельно: автосохранение по таймеру при фокусе в редакторе форматированного текста сохранило набранное.

**Часть B. Проверка и печать (B1–B5)**

**B1. Жизненный цикл проверки** — `DocumentTransitions` по статусу и роли (`DocumentRole`: автор или проверяющий):
- отправка `draft`/`saved_draft`/`returned` → `under_review` — автор, только при полной проверке без ошибок;
- возврат `under_review` → `returned` и приём `under_review` → `accepted` — методист (политика `reviewers`, только роль `methodist`); возврат — при хотя бы одном неразрешённом замечании (FR-REV-03), приём — когда неразрешённых замечаний нет (предусловие UC-07);
- правка методистом в `under_review` без смены статуса (FR-REV-11); на проверке и после приёма документ для автора закрыт;
- каждая смена статуса проверки — запись в `document_status_history` и снимок `status_change`. Правка методиста даёт свой снимок версии: автосохранение перезаписывает рабочий снимок только того же человека, поэтому в истории версий видно, кто правил (`saved_by`). Запись истории и снимки вынесены в `DocumentHistory` — общие для правки и проверки.

*Согласовано: доработка в статусе `returned` — отступление от UC-06 и таблицы переходов проекта* (там «на доработке → черновик при доработке»). Правки автора, автосохранение и «Сохранить» статус `returned` не меняют («Сохранить» — снимок `manual_save`); повторная отправка — `returned → under_review` с той же полной проверкой. Причины: статус сигнализирует, что документ на доработке; на нём держится отчёт о сроках доработки; замечания остаются в контексте.

*Замечания* — `document_comments` (миграция `AddDocumentComments`): поле — JSON Pointer (в проекте — JSONPath; Pointer — как в ошибках проверки), текст, автор, время, признак «разрешено» с автором (`resolved_by` — дополнение к проекту) и временем; ограничение связывает признак с автором и временем разрешения. Место замечания проверяется по схеме документа (`SchemaInspector.SubschemaAt`). Замечания не удаляются. Общий комментарий при возврате необязателен: без него в истории — «Замечаний: N» (по проекту комментарий обязателен; *согласовано с автором*: замечания к полям уже объясняют возврат).

**B6. PDF и фоновое формирование**
- *Конвертер* — Gotenberg 8.38.1 (лицензия MIT): LibreOffice 26.8 в режиме headless за HTTP API (`POST /forms/libreoffice/convert`), сервис `converter` в `docker-compose.yml`. Образ — около 2,5 ГБ: в нём LibreOffice, Chromium и шрифты. Свой образ с LibreOffice был бы меньше, но потребовал бы своей обёртки HTTP и сопровождения; для прототипа выбран готовый сервис с закреплённой версией. Хост обращается к нему через `IPdfConverter` (`GotenbergPdfConverter`, `Converter:Url`, `Converter:TimeoutSeconds`).
- *Шрифты.* Times New Roman в образе нет, а шрифты Microsoft в образ не добавлялись (их лицензия не для свободного распространения в составе образа). LibreOffice подставляет метрически совместимый Liberation Serif: ширины символов те же, поэтому переносы строк и разбиение на страницы совпадают с расчётом на Times New Roman. В PDF — Liberation Serif (и Carlito вместо Calibri); начертание чуть отличается, на вёрстку это не влияет. РПД по дисциплине Б1.О.10 — 11 страниц, конвертация около 1 с. DOCX по-прежнему ссылается на Times New Roman и в Word открывается с ним.
- *Фон (FR-GEN-04).* `POST /api/documents/{id}/print/{docx|pdf}` ставит задачу в очередь Hangfire `generation` и отвечает 202 со ссылкой на статус. Очередь обслуживает отдельный сервер Hangfire (`Jobs:GenerationWorkers`, по умолчанию 2) — долгий импорт не задерживает печать. Задача: DOCX → при необходимости PDF → файлы в `generated_files`; статус (`queued` → `running` → `succeeded`/`failed`), причина ошибки и отчёт — в `generation_tasks`. Автоповтора нет, как и у импорта: неудачу видит пользователь и формирует заново, повтор через минуты только запутал бы. Конвертер недоступен — задача PDF завершается с причиной «Конвертер PDF недоступен (адрес): …»; DOCX формируется отдельной кнопкой и от конвертера не зависит.
- `GET …/generations` — последние задачи документа, `GET …/generations/{taskId}` — статус для опроса, `GET …/files/{fileId}` — файл (истёкший или удалённый — 404).
- *Очистка* — регулярная задача `generated-files-cleanup` раз в сутки: файлы с истёкшим `expires_at` удаляются с диска и из `generated_files`.
- *Тесты* — с поддельным конвертером (`FakePdfConverter`): DOCX действительно уходит на конвертацию, отказ конвертера — задача `failed` с причиной, очистка удаляет истёкшие файлы. Настоящий Gotenberg проверен вручную.

- Предпросмотр PDF (S-16, точный режим FR-DOC-10): файл получается запросом с токеном, показывается во встроенном просмотрщике браузера по ссылке на данные в памяти (`blob:`), после успешного PDF открывается сам. Прямая ссылка без токена не открылась бы. Черновой HTML-режим — перспектива: его роль выполняет редактор.
- *Проверено в браузере* (автор, РПД по Б1.О.10 по второй версии шаблона): DOCX и PDF сформированы в фоне, отчёт — одно предупреждение (не найден председатель УМК: такой категории в файле должностей нет) и незаполненные места, в том числе оставленные бланки протокола; PDF открылся в панели. Панель методиста в браузере не проверялась — проверено тестами API (методист печатает только документы на проверке и принятые).

**Итог.** РПД проходит проверку: отправка с полной проверкой (схема, условные разделы, правила; ошибки и предупреждения ведут к полям), очередь методиста, замечания к полям, возврат и доработка в статусе «на доработке», повторная отправка, приём. Подписанты находятся по справочнику цепочкой правил. По документу формируются DOCX по второй версии DWP-шаблона — титул, трудоёмкость, таблицы, методическое содержимое, подписанты, заглушки и бланки — и PDF через Gotenberg; формирование идёт в фоне, файлы хранятся 30 дней, PDF открывается в браузере. Тестов — 248 (25 + 223), сборка без предупреждений.
