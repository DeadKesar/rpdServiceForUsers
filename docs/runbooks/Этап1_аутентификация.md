# Прототип. Этап 1: аутентификация (runbook)

*Рабочий документ этапа реализации и материал для главы 4. Файлы этапа — в `rpd-fos-stage1.zip`: новые и изменённые файлы, которые накладываются поверх репозитория.*

## Решения этапа

- **Сервер авторизации — OpenIddict (Apache 2.0) внутри хоста API.** OpenID Connect сохраняется, лицензионный риск 9 снят, отдельного контейнера нет.
- **Учётные записи — ASP.NET Core Identity** в той же базе данных. Пароли хранятся только там, в виде хеша. Самостоятельной регистрации нет: учётные записи создаёт Администратор.
- **Веб-клиент — Blazor WebAssembly, его раздаёт тот же хост.** Один адрес, CORS не нужен.
- **Поток — authorization code + PKCE.** Токены доступа проверяет тот же хост, без обращения к внешнему серверу.
- **Основа — официальный пример OpenIddict «Balosar»** (.NET 10, OpenIddict 7.7.2). Упрощено для собственного клиента: без экрана согласия и внешних провайдеров входа, своя страница входа на русском.
- **Токены хранятся в браузере** (sessionStorage) — осознанное упрощение прототипа. Защита: санитизация форматированного текста (этап 4) и короткоживущие токены. Паттерн BFF — перспектива; у OpenIddict для него есть официальный пример «Dantooine».
- **У пользователя одна роль** — ограничение прототипа: клиентская библиотека Blazor без доработки не разбирает массив ролей.

## Шаги этапа 1

**1. HTTPS для разработки.** OpenIddict принимает запросы только по HTTPS.
```
dotnet dev-certs https --trust
```

**2. Веб-клиент из шаблона.** Шаблон с ключом `-au Individual` сразу подключает библиотеку аутентификации Blazor: страницы входа и выхода, перенаправление на вход.
```
dotnet new blazorwasm -au Individual -o src/RpdFos.Web
dotnet sln add src/RpdFos.Web
dotnet add src/RpdFos.Web package Microsoft.Extensions.Http
```

**3. Пакеты и ссылка хоста на клиент.**
```
dotnet add src/RpdFos.Core package Microsoft.AspNetCore.Identity.EntityFrameworkCore
dotnet add src/RpdFos.Core package OpenIddict.EntityFrameworkCore
dotnet add src/RpdFos.Api package OpenIddict.AspNetCore
dotnet add src/RpdFos.Api package Microsoft.AspNetCore.Components.WebAssembly.Server
dotnet add src/RpdFos.Api reference src/RpdFos.Web
```

**4. Файлы этапа — поверх репозитория.** Строго после шага 2: архив заменяет `Program.cs` клиента, созданный шаблоном.
```
Expand-Archive "$env:USERPROFILE\Downloads\rpd-fos-stage1.zip" -DestinationPath C:\work -Force
```

**5. Пункты меню.** В `src/RpdFos.Web/Layout/NavMenu.razor` после последнего блока `nav-item` добавить:
```razor
<div class="nav-item px-3">
    <NavLink class="nav-link" href="templates">Шаблоны</NavLink>
</div>
<AuthorizeView Roles="admin">
    <div class="nav-item px-3">
        <NavLink class="nav-link" href="users">Пользователи</NavLink>
    </div>
</AuthorizeView>
```

**6. Сборка.** `dotnet build` — без ошибок. Если ошибки есть, присылай вывод целиком: код собран по официальному примеру, но у меня здесь нет доступа к NuGet.

**7. Миграция.**
```
dotnet ef migrations add AddIdentity -p src/RpdFos.Core -s src/RpdFos.Api
```
В методе `Up` должны появиться таблицы Identity (`AspNetUsers`, `AspNetRoles`, `AspNetUserRoles` и др.) и OpenIddict (`OpenIddictApplications`, `OpenIddictAuthorizations`, `OpenIddictScopes`, `OpenIddictTokens`). Имена этих таблиц библиотеки задают явно, поэтому соглашение snake_case их не меняет; колонки — в snake_case. Это служебные таблицы библиотек, оставляем как есть; в SQL их имена пишутся в кавычках.

**8. Первый администратор.** Пароль хранится в user-secrets на твоём компьютере и в репозиторий не попадает.
```
dotnet user-secrets init --project src/RpdFos.Api
dotnet user-secrets set "Seed:AdminEmail" "admin@rpdfos.local" --project src/RpdFos.Api
dotnet user-secrets set "Seed:AdminPassword" "<пароль>" --project src/RpdFos.Api
```
Требования к паролю: не короче 8 символов, заглавная и строчная буквы, цифра и спецсимвол. В PowerShell пароль лучше брать в одинарные кавычки: в двойных знак `$` воспринимается как переменная.

**9. Запуск и проверка в браузере.**
```
dotnet run --project src/RpdFos.Api
```
Первый профиль в `launchSettings.json` теперь `https`: откроется https://localhost:5081. При первом запуске применится миграция и создадутся роли, клиент OIDC и администратор.

| Действие | Ожидается |
| --- | --- |
| https://localhost:5081/.well-known/openid-configuration | JSON с `authorization_endpoint` и `token_endpoint` |
| Главная страница → «Log in» | Страница «Вход» на русском |
| Вход администратором | Возврат в приложение, в шапке — имя «Администратор» |
| «Шаблоны» | Список шаблонов, созданных на этапе 0 |
| «Создать тестовый шаблон» | «Шаблон создан.» |
| «Пользователи» → создать преподавателя | «Пользователь … создан.» |
| Выход, вход преподавателем | Пункта «Пользователи» в меню нет |
| «Создать тестовый шаблон» под преподавателем | «Недостаточно прав … (403)» |
| Swagger UI: `GET /api/templates` | 401 — так и должно быть: Swagger обращается без токена |

**10. Тесты.** `dotnet test` → 9 тестов зелёные: 7 прежних и 2 новых (API закрыт без токена; сервер публикует настройки).

## Если что-то не так

| Симптом | Что делать |
| --- | --- |
| `dotnet new` не знает ключ `-au Individual` | Сообщи — дам файлы аутентификации клиента вручную |
| Браузер предупреждает о сертификате | `dotnet dev-certs https --trust`, перезапустить браузер |
| «This server only accepts HTTPS requests» | Открывать https://localhost:5081, а не http://localhost:5080 |
| После входа ошибка про `redirect_uri` | Адрес в браузере должен совпадать с `Auth:PublicUrl`. Клиент OIDC создаётся один раз; после смены адреса удалить его: `docker compose exec db psql -U rpdfos -c 'delete from "OpenIddictApplications";'` и перезапустить |
| В логе «Первый администратор не создан» | Не выполнен шаг 8, или запуск не в окружении Development |
| Ошибка при создании администратора о пароле | Пароль не проходит требования шага 8 |
| После верного пароля снова открывается вход | Проверить, что браузер не блокирует cookie; прислать лог приложения |
| Меню не учитывает роль | У пользователя больше одной роли — в прототипе поддерживается одна |
| Ошибки сборки в `RpdFos.Web` после шага 4 | Шаблон мог разложить файлы иначе — прислать вывод |
