# Стенд апробации (runbook)

*Рабочий документ этапа 8. Комплект — папка `deploy/`: `docker-compose.yml`, настройки nginx, выпуск сертификатов, образец настроек. Почтовый сервер стенда — раздел 7; резервные копии — раздел 8.*

## Что поднимается

| Служба | Образ | Назначение |
| --- | --- | --- |
| `proxy` | `nginx:1.30.8` | HTTPS (TLS 1.2 и 1.3), порты 80 и 443; с 80 — перенаправление на 443 |
| `api` | `rpdfos-api:stand` (собирается из репозитория) | Хост: API, сервер авторизации, фоновые задачи, клиент Blazor |
| `db` | `postgres:17-alpine` | База данных |
| `converter` | `gotenberg/gotenberg:8.38.1` | DOCX → PDF |
| `mail` | `boky/postfix:5.2.1-alpine` | Свой почтовый сервер стенда, только на отправку (раздел 7) |
| `backup` | `postgres:17-alpine` | Ежедневная копия базы в папку компьютера, хранятся 30 последних (раздел 8) |
| `certs` | `nginx:1.30.8` | Выпуск сертификатов; запускается только вручную |

Наружу открыты только 80 и 443. База и конвертер — во внутренней сети без выхода в интернет. Почтовый сервер видит только хост API (отдельная сеть из двух служб), портов наружу у него нет. Данные — в томах `rpdfos-stand_dbdata` (база), `rpdfos-stand_appdata` (ключи Data Protection и сформированные файлы), `rpdfos-stand_mailqueue` (очередь писем) и `rpdfos-stand_maildkim` (ключ подписи DKIM).

## 1. Требования к компьютеру

- **Система:** Linux с Docker Engine 25 или новее и плагином compose либо Windows 10/11 с Docker Desktop (контейнеры Linux, WSL 2; версия с Engine 25+ — проверка здоровья службы копий требует `start_interval`). Условия бесплатного использования Docker Desktop сверить с лицензией до установки; Docker Engine на Linux — Apache 2.0.
- **Ресурсы:** 4 ядра, 8 ГБ памяти, 30 ГБ свободного места. Образы занимают около 4 ГБ, столько же временно нужно на сборку.
- **Интернет** — на время установки и обновления (образы и пакеты). В работе наружу выходит только почта.
- **Постоянное имя или адрес в сети кафедры:** запись DNS у ИТ-службы или закреплённый адрес (резервирование DHCP). При смене имени или адреса сертификат выпускается заново (раздел 6).
- **Порты 80 и 443** свободны (на Windows их часто занимает IIS).
- **Круглосуточная работа:** сон и гибернация выключены.

Запуск после перезагрузки:

- Linux: `sudo systemctl enable docker` — контейнеры поднимаются сами (`unless-stopped`).
- Windows: Docker Desktop запускается при входе пользователя, а не при включении компьютера. Включить Settings → General → «Start Docker Desktop when you sign in» и настроить автоматический вход пользователя; без него после перезагрузки (в том числе после обновлений Windows) нужно войти вручную.

Вход в сеть на Windows (PowerShell от администратора):

```powershell
New-NetFirewallRule -DisplayName "RPD-FOS stand" -Direction Inbound -Protocol TCP -LocalPort 80,443 -Action Allow -Profile Domain,Private
```

## 2. Установка с нуля

Все команды — в папке `deploy`. В Linux вместо `Copy-Item` — `cp`.

**1. Исходники.** Клонировать репозиторий или распаковать его архив, перейти в `deploy`.

**2. Настройки.**

```powershell
Copy-Item .env.example .env
```

Заполнить `.env`:

| Настройка | Что указать |
| --- | --- |
| `STAND_HOST` | Имя стенда строчными латинскими буквами или его адрес IPv4, без `https://` |
| `STAND_IP` | Постоянный адрес IPv4: попадёт в сертификат вместе с именем. Нет постоянного — пусто |
| `DB_PASSWORD`, `CERT_PASSWORD` | Пароли базы и сертификатов входа: только латинские буквы и цифры |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Первый администратор. Пароль — в одинарных кавычках, не короче 8 символов: заглавная и строчная буквы, цифра, спецсимвол |
| `MAIL_*` | Пусто: почта выключена, уведомления работают только в интерфейсе. Включение — раздел 7 |

Случайный пароль:

```powershell
docker run --rm nginx:1.30.8 openssl rand -hex 24
```

`.env` содержит пароли: доступ — только администратору стенда (в Linux `chmod 600 .env`), в git файл не попадает.

**3. Сертификаты.** Команда выпускает корневой сертификат, сертификат стенда и сертификаты входа (папка `certs`, вне git):

```powershell
docker compose run --rm certs
```

В выводе — отпечаток (SHA-256) корневого: он понадобится при установке на компьютеры.

**4. Запуск.** Первый раз — до 15 минут (загрузка образов и сборка):

```powershell
docker compose up -d --build --wait
```

Хост сам применяет миграции и создаёт роли, клиента OIDC и первого администратора. Ничего тестового в базе нет.

**5. Корневой сертификат** — на компьютеры кафедры (раздел 3), включая тот, с которого работает администратор.

**6. Проверка.** `https://<имя стенда>/health` отвечает `{"status":"ok"}`, `https://<имя стенда>` открывает главную страницу без предупреждения браузера, «Войти» — страницу входа. Все службы — `healthy`:

```powershell
docker compose ps
```

**7. Первый вход и уборка.** Войти администратором, сменить пароль в профиле, затем **очистить `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`** и выполнить `docker compose up -d`. Иначе, если администратор сменит email, при следующем запуске хост создаст второго администратора с паролем из `.env`.

**8. Ключ корневого** `certs/ca/ca.key` перенести на отдельный носитель и удалить со стенда: он нужен только для перевыпуска.

## 3. Корневой сертификат на компьютерах кафедры

Файл — `certs/ca/rpdfos-ca.crt` (открытая часть, секрета в нём нет). Он ограничен именем и адресом стенда: подписать им сертификат другого сайта нельзя.

Перед установкой сверить отпечаток с выводом `docker compose run --rm certs show`:

```powershell
(Get-PfxCertificate .\rpdfos-ca.crt).GetCertHashString("SHA256")
```

Windows, PowerShell от администратора — для всех пользователей компьютера (Edge, Chrome):

```powershell
certutil -addstore -f Root .\rpdfos-ca.crt
```

Без прав администратора — только для текущего пользователя:

```powershell
certutil -user -addstore Root .\rpdfos-ca.crt
```

- Много компьютеров в домене — групповой политикой: «Доверенные корневые центры сертификации».
- Firefox берёт корневые Windows при включённой настройке `security.enterprise_roots.enabled` (`about:config`); иначе — Настройки → Приватность и защита → Сертификаты → Просмотр → Центры → Импортировать.
- Linux (Debian, Ubuntu): `sudo cp rpdfos-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates`; браузеру — импорт в его настройках.
- Имя стенда не определяется в сети — строка в `hosts` компьютера: `<адрес> <имя>`.

Удалить после апробации (найти по имени `RPD-FOS stand root`): `certmgr.msc` или

```powershell
certutil -delstore Root "RPD-FOS stand root (<имя стенда>)"
```

**Запасной путь** — самоподписанный сертификат: корневой ставить не нужно, но браузер предупреждает на каждом компьютере.

```powershell
docker compose run --rm certs self-signed
```

```powershell
docker compose restart proxy
```

## 4. Обновление версии

Перед обновлением сделать копию базы (раздел 8, `backup now`): миграции назад не откатываются. Затем обновить исходники (`git pull` или новый архив поверх, сохранив `.env` и `certs`) и выполнить:

```powershell
docker compose build --pull api
```

```powershell
docker compose up -d --wait
```

Прокси, база и конвертер продолжают работать; хост перезапускается за полминуты, входы сохраняются (ключи — на томе). Пользователям — обновить страницу (Ctrl+F5). Появились новые строки в `.env.example` — добавить их в `.env`.

## 5. Остановка и журналы

| Действие | Команда |
| --- | --- |
| Остановить до следующего `start` | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Снять контейнеры, данные остаются | `docker compose down` |
| **Удалить вместе с данными** | `docker compose down -v` |
| Журнал хоста | `docker compose logs -f --tail 100 api` |

`docker compose stop` запоминается: после перезагрузки остановленные службы сами не поднимутся. Журналы ограничены 50 МБ на службу. Журнал nginx — без строки запроса: в ней бывают токены ссылок из писем.

## 6. Сертификаты: сроки и замена

| Сертификат | Срок | Замена |
| --- | --- | --- |
| Корневой | 10 лет | `docker compose run --rm certs ca` — и заново на все компьютеры |
| Стенда | 820 дней | `docker compose run --rm certs stand`, затем `docker compose restart proxy`; корневой тот же (вернуть `ca.key` на время выпуска) |
| Входа (подпись и шифрование токенов) | 5 лет | `docker compose run --rm certs auth`, затем `docker compose restart api`; пользователи входят заново |

- Сменились имя или адрес: исправить `.env`, `docker compose run --rm certs ca`, `docker compose up -d --force-recreate proxy api`, новый корневой — на компьютеры (старый удалить). Адреса возврата входа хост обновит сам.
- Сменился `CERT_PASSWORD`: `docker compose run --rm certs auth`, затем `docker compose up -d`.
- Сменить `DB_PASSWORD` у работающей базы: сначала `docker compose exec db psql -U rpdfos -c "\password"`, затем `.env` и `docker compose up -d`.
- Сроки и отпечатки: `docker compose run --rm certs show`.

## 7. Почта

Письма отправляет хост API: уведомления, дайджест, напоминания, «Забыли пароль?», приглашение, подтверждение email. Он отдаёт их службе `mail` (Postfix) — та доставляет на серверы получателей сама или через ретранслятор. Служба принимает письма только от хоста, только от отправителей своего домена и ничего не пересылает чужим; из интернета до неё не достучаться, порт не опубликован.

**Включить.** В `.env`:

| Настройка | Что указать |
| --- | --- |
| `MAIL_ENABLED` | `true` |
| `MAIL_FROM` | Отправитель: `АС РПД и ФОС <адрес>`; адрес — в домене стенда или того, кто разрешил слать от своего имени |
| `MAIL_DOMAIN` | Домен адреса из `MAIL_FROM`: письма от других доменов сервер отвергает |
| `MAIL_HOSTNAME` | Имя сервера в приветствии; пусто — `STAND_HOST` |

`MAIL_HOST`, `MAIL_PORT`, `MAIL_SECURITY` оставить пустыми: хост сам идёт на `mail:587` без входа и шифрования (сеть из двух служб). Затем `docker compose up -d`.

**Исходящий порт 25.** Доставка напрямую идёт с порта 25 компьютера на серверы получателей. Многие провайдеры и сети его закрывают. Проверка с компьютера стенда:

```powershell
Test-NetConnection <почтовый сервер получателя> -Port 25
```

Закрыт — письма останутся в очереди. Два пути: **ретранслятор** (почтовый сервер организации или провайдера, который принимает от стенда) — `MAIL_RELAY=[сервер]:587`, `MAIL_RELAY_USER`, `MAIL_RELAY_PASSWORD`; либо работать без почты: уведомления видны в интерфейсе, пароли новым пользователям задаёт администратор (временный пароль со сменой при первом входе).

**Чтобы письма не попадали в спам.** Сервер получателя проверяет, кто отправляет:

- *Имя и обратная запись.* У стенда есть имя с A-записью на внешний адрес сети, а у этого адреса — обратная запись (PTR) на то же имя. Её заводит тот, кому принадлежит адрес: ИТ-служба или провайдер. `MAIL_HOSTNAME` — это имя.
- *SPF.* TXT-запись домена из `MAIL_DOMAIN`: `v=spf1 ip4:<внешний адрес сети> ~all`.
- *DKIM*, если у стенда свой домен: `MAIL_DKIM=1`, `docker compose up -d`; открытая часть ключа — в журнале при первом запуске или командой ниже, её заносят в DNS записью `mail._domainkey.<домен>` типа TXT. Ключ хранится на томе и не меняется при пересоздании контейнера.
- Без своего домена (имя вида `.local` или `.localhost`, адрес из частной сети) настоящие серверы письма чаще всего отвергают или кладут в спам: нужен ретранслятор или корпоративный сервер.

```powershell
docker compose exec mail sh -c "cat /var/lib/rspamd/dkim/*.mail.txt"
```

**Очередь и журнал.** Не принятое получателем письмо остаётся в очереди и повторяется несколько дней, затем сервер возвращает отправителю отчёт о недоставке.

```powershell
docker compose exec mail postqueue -p          # очередь
docker compose exec mail postqueue -f          # повторить сейчас
docker compose logs --tail 100 mail            # ответы серверов получателей: status=sent или bounced с кодом
```

Хост не повторяет письмо старше суток (`Mail:MaxAgeHours`): событие остаётся в интерфейсе, а письмо по нему уже не уходит.

**Перейти на корпоративный сервер** — менять только настройки `Mail` в `.env`, ни хост, ни образ не пересобираются:

```
MAIL_ENABLED=true
MAIL_HOST=<сервер>
MAIL_PORT=587
MAIL_USER=<логин>
MAIL_PASSWORD='<пароль>'
MAIL_SECURITY=StartTls
MAIL_FROM=АС РПД и ФОС <адрес, который разрешён серверу>
```

Затем `docker compose up -d` и `docker compose stop mail` (после остановки её не поднимет и перезагрузка компьютера). Порт и режим шифрования — по требованиям администратора сервера: 587 с `StartTls` или 465 с `SslOnConnect`; без входа внутри сети — `MAIL_SECURITY=None`. Адрес отправителя должен быть тем, от имени которого этот сервер принимает письма.

## 8. Резервные копии и восстановление

Служба `backup` каждую ночь снимает копию базы (`pg_dump`) и кладёт её в папку на компьютере. В базе лежат всё невосстановимое: исходные файлы (учебные планы, списки компетенций, матрицы), шаблоны оформления, рисунки, документы, пользователи, журнал. Поэтому копии базы достаточно. Сформированные PDF и DOCX в копию не входят: их формируют заново, а хранятся они 30 дней.

| Настройка `.env` | Смысл |
| --- | --- |
| `BACKUP_DIR` | Папка копий: `D:/rpdfos-backups` (Windows, косые черты вперёд) или `/var/backups/rpdfos` (Linux). **Лучше другой диск**, чем у тома базы, и, если можно, сетевая папка или съёмный носитель: копия на том же диске не спасёт от его отказа. Пусто — `deploy/backups` |
| `BACKUP_TIME` | Время ежедневной копии по Москве, `ЧЧ:ММ`; пусто — `03:00` |
| `BACKUP_KEEP` | Сколько последних копий хранить; пусто — 30 |

- Копия делается в `rpdfos-ГГГГММДД-ЧЧММСС.dump`; лишние старые удаляются только после удачной новой. Если компьютер ночью был выключен, копия делается сразу после его включения; при ошибке служба повторяет попытку каждый час.
- Состояние службы — `docker compose ps backup`: `unhealthy`, если за последние сутки копии не было. Журнал — `docker compose logs backup`.
- Размер папки: `BACKUP_KEEP` × размер одной копии. Копия базы разработки (23 учебных плана, 46 шаблонов, 57 документов, 40 исходных файлов) — около 7 МБ; для апробации хватит единиц гигабайт, но место под папку надо предусмотреть.

Команды (в папке `deploy`):

| Действие | Команда |
| --- | --- |
| Копия сейчас (перед обновлением) | `docker compose run --rm backup now` |
| Список копий | `docker compose run --rm backup list` |
| Проверить последнюю копию (или названную) | `docker compose run --rm backup verify` |

**Проверка копий.** `verify` восстанавливает копию во временную базу, не трогая базу стенда, и показывает число записей: сотрудников, учебных планов, шаблонов, документов, исходных файлов, рисунков и последнюю миграцию. Проверять раз в неделю и после каждого обновления: копия, которую не удалось восстановить, — не копия.

**Что копировать вручную, один раз** (в служебную копию эти файлы не входят; хранить отдельно от компьютера и от копий базы, они содержат секреты):

| Что | Зачем | Как |
| --- | --- | --- |
| `deploy/.env` | Пароли базы, сертификатов и почты | Скопировать файл |
| `deploy/certs/` | Сертификаты стенда и входа; **ключ корневого `certs/ca/ca.key` — отдельно на носителе** (раздел 2, шаг 8) | Скопировать папку |
| Ключи Data Protection | Без них после восстановления пользователям придётся войти заново, а ссылки из писем перестанут действовать; данных они не хранят | Команда ниже |

```powershell
docker run --rm -v rpdfos-stand_appdata:/data:ro -v "${PWD}/keys-backup:/out" postgres:17-alpine sh -c "cp -a /data/keys/. /out/"
```

Ключи меняются редко (раз в 90 дней добавляется новый), поэтому копию достаточно обновлять после смены `.env` и раз в квартал.

### Восстановление

Копия сначала разворачивается во временную базу и подменяет базу стенда только после успешного восстановления: неудача базу не тронет.

**Сломалась база или её том (чистый стенд, данных нет).**

1. Остановить хост, чтобы никто не работал с базой: `docker compose stop api`. Если том базы удалён или повреждён — снять стенд и создать том заново:

```powershell
docker compose down
```

```powershell
docker volume rm rpdfos-stand_dbdata
```

2. Восстановить последнюю копию (или названную: имя файла из `list`; чужой файл сначала положить в папку копий). Команда поднимет пустую базу сама:

```powershell
docker compose run --rm backup restore
```

3. Если ключи Data Protection тоже потеряны — вернуть их (иначе — пропустить):

```powershell
docker run --rm -v rpdfos-stand_appdata:/data -v "${PWD}/keys-backup:/in:ro" postgres:17-alpine sh -c "mkdir -p /data/keys && cp -a /in/. /data/keys/ && chown -R 1654:1654 /data/keys"
```

4. Запустить стенд и проверить вход, документы, шаблоны: `docker compose up -d --wait`.

**Вернуться к прежним данным в работающем стенде** (например, ошибочно удалили документы): остановить хост (`docker compose stop api`), затем

```powershell
docker compose run --rm backup restore rpdfos-20261125-030000.dump --replace
```

`--replace` нужен, если в базе уже есть данные: перед заменой команда сохраняет их копией `before-restore-…` (её сохранение не входит в 30 хранимых — удалить вручную, когда она не нужна). Всё, что внесено после копии, пропадёт.

После восстановления сформированные файлы, которых нет в томе, скачать нельзя («файл удалён по сроку хранения»): сформировать документ заново.

**Копия из старой версии.** Хост сам применяет миграции при запуске, поэтому копию старой версии можно восстановить на новой. Обратное — нет.

## 9. Если не работает

| Признак | Причина и действие |
| --- | --- |
| compose: «required variable … is missing» | Не заполнена строка `.env`, её имя — в сообщении |
| `proxy` перезапускается, в журнале `cannot load certificate` | Сертификаты не выпущены: шаг 3 установки |
| `api` перезапускается | `docker compose logs api`: текст ошибки называет настройку (сертификаты, пароль, адрес) |
| Ответ 502 | Хост ещё запускается или остановлен: `docker compose ps` |
| Предупреждение браузера | Корневой не установлен на этом компьютере или стенд открыт не по `STAND_HOST` и не по `STAND_IP` |
| «Порт уже занят» при запуске | 80 или 443 занят другой программой (IIS, веб-сервер) |
| После входа — ошибка адреса возврата | Стенд открыт не по `STAND_HOST`: вход работает только по этому имени |
| PDF не формируется | `docker compose ps converter`; журнал — `docker compose logs converter` |
| Письма не приходят | `MAIL_ENABLED=true`? `docker compose logs mail`: `Connection timed out` — порт 25 закрыт сетью, нужен ретранслятор; `Recipient address rejected: Domain not found` — домена адреса нет в DNS (опечатка; на странице «Пользователи» — «Проверьте адрес…»); `Recipient address rejected` и коды 5xx — сервер получателя отказал; письма нет в журнале — смотреть журнал `api` (`MAIL_FROM`, `MAIL_DOMAIN`) |
| `backup` в состоянии `unhealthy` | Копии не делаются больше суток: `docker compose logs backup` — база недоступна, папка копий не пишется (`BACKUP_DIR`, права, место на диске) |
| Письма в спаме | SPF, DKIM, обратная запись и имя — раздел 7 |
