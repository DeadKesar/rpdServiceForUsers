# Идеи за пределами заданий

*Замечено по ходу работы, в текущее задание не входит. Решение — за автором.*

- **Сообщить авторам Corvus.JsonSchema об ошибке `format: "regex"`.** Версия 5.7.9 при утверждении форматов считает `"\\."` (экранированную точку) неверным регулярным выражением, хотя для ECMA-262 оно верно, и сама же компилирует такой `pattern` без ошибок. Обойдено: метасхема проверяется без утверждения форматов.
- **Назначение дисциплин преподавателям (перспектива).** Сейчас любой преподаватель может создать РПД по любой дисциплине плана, если документа по ней ещё нет (этап 4, B3). В вузе дисциплины закрепляет кафедра: назначение «дисциплина — преподаватель» ограничило бы создание и список «Мои документы» закреплёнными дисциплинами.
- **Правила каталога без реализации** (на этапе 5 реализованы три, `hours_match_curriculum` — в этапе 5.2, B1.1, предупреждением): `all_indicators_covered` (каждый индикатор матрицы — хотя бы в одной теме), `unique_competence_codes`, `literature_main_count`, правила ФОС. Имена в схемах есть, при проверке пропускаются.
- **Автору — уведомление о ручном запуске согласования (этап 6.1, C3).** Когда документ ждал назначения согласующих и методист запустил согласование кнопкой, автор получил только прежнее «принят — ждёт назначения»: что ожидание кончилось, ему не сообщается (такого события в задании C3 нет). Можно добавить одно уведомление «согласование начато».
- **Заменённый согласующий и его уведомление (этап 6.1, C3).** При замене согласующего на идущем круге прежний остаётся с непрочитанным «ждёт вашего согласования», а документ из его очереди уже ушёл; переход по этому уведомлению даст ему 403. Если станет заметно — событие «вы больше не согласующий документа» или скрытие уведомлений о документе, к которому доступа нет.
- **Индекс ленты и очистка уведомлений (этап 6.1, C3).** Частичный индекс `notifications` — только по непрочитанным (счётчик); для ленты «последние уведомления получателя» подходящего индекса нет. На прототипе строк мало; при росте — индекс `(recipient_id, created_at DESC)` новой миграцией и очистка старых прочитанных уведомлений по сроку.
- **«Отмеченные мной» растёт без границы (этап 6.1, C4).** Строки круга согласованного документа остаются в `document_signatures` навсегда, поэтому список согласующего копит все его документы за всё время — без страниц и фильтров. На прототипе документов мало; при росте — показывать последние (например, 50) или добавить фильтр по статусу документа и срокам.
- **Один председатель УМК на несколько направлений (этап 6.1, C6).** Колонка `users.direction_id` (по заданию C6) связывает запись с одним направлением; если один человек возглавляет комиссию двух направлений, в справочнике нужны две записи на него. Если такое окажется обычным, вместо колонки нужна таблица связи «председатель — направление» (миграция и правка резолвера и страницы справочника).
- **Правка названия кафедры (этап 6.1, C7).** Опечатка из плана, загруженного первым («Социология, политология и нормативно-правовове регулирование промышленного развития» из 15.03.01 набора 2023), закрепляется в справочнике: план того же года с верным написанием название не меняет (правило A7), а правки названия кафедры в интерфейсе нет. Название печатается на титуле новых РПД кафедры. Достаточно правки названия на странице администратора с записью в аудит.
- **Обрыв связи на остальных страницах клиента (этап 7, A1).** В A1 обрыв связи (`HttpRequestException` без кода статуса) перехвачен на панели печати и странице справочника сотрудников; опрос колокольчика ловил его и раньше. Остальные страницы и действия — в том числе сохранение раздела в `DocumentEditor` (`SaveSectionAsync`, его вызывает печать), — ловят только `AccessTokenNotAvailableException`: при остановленном сервере они по-прежнему дают полосу «Произошла непредвиденная ошибка» и `crit` в консоли. Общее решение — `ErrorBoundary` в `MainLayout` с сообщением «Нет связи с сервером» и кнопкой «Повторить» либо тот же приём на каждой странице; выбор за автором. Ответы сервера с кодом ошибки (404, 500) на `GetFromJsonAsync` тоже остаются необработанными исключениями.
- **`PrintPanel` перечитывает список формирований при каждой перерисовке страницы документа (этап 7, A1).** `OnParametersSetAsync` вызывает `LoadAsync`, а параметр `BeforePrint` — делегат, который Blazor считает изменившимся при каждой перерисовке родителя. Достаточно перечитывать при смене `DocumentId` и после формирования. Не измерялось: число запросов на практике не смотрели.
