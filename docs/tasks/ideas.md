- **Ручная привязка строк матрицы к дисциплинам плана (перспектива).** Сейчас матрица сопоставляется с планом только по названиям, несопоставленные строки остаются замечаниями импорта. В интерфейсе импорта методист мог бы привязать такую строку к дисциплине плана вручную (например, «Внедрение и эксплуатация информационных систем» → Б1.В.ДВ.03.01 после переименования электива).
- **Должности, исчезнувшие из файла (вопрос модели).** Импорт обновляет и добавляет записи справочника сотрудников, но не деактивирует те, чьего «Офиц. названия» в новом файле нет. Пример: после исправления опечатки «…и управление» запись со старым названием осталась активной. Варианты: деактивировать отсутствующие в файле справочные записи (не связанные с учётной записью) или оставить — решение за автором.
- **Деактивация записи, связанной с учётной записью.** Если на должности сменился человек, а прежняя запись связана с учётной записью (`can_login`), она тоже становится неактивной — и загрузка файлов от этой учётной записи вернёт 403. Вероятно, у связанной записи стоит снимать только должность и категорию подписанта, а саму запись оставлять активной.
- **Страница «Шаблоны» показывает коды** `rpd`, `empty`, `published` вместо русских названий типа и статуса (страница этапа 1).
- **Шум в консоли клиента.** Blazor пишет в консоль браузера info-сообщения «Authorization failed» от каждой проверки ролей в меню; достаточно уровня Warning для клиента (`builder.Logging.SetMinimumLevel`).
- **Привязка к справочнику на странице «Пользователи».** API принимает `directoryUserId`, но на странице выбора записи справочника нет — учётная запись всегда получает новую запись.
