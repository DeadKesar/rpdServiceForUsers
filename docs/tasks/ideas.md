# Идеи за пределами заданий

*Замечено по ходу работы, в текущее задание не входит. Решение — за автором.*

- **Шум в консоли клиента.** Blazor пишет в консоль браузера info-сообщения «Authorization failed» от каждой проверки ролей в меню; достаточно уровня Warning для клиента (`builder.Logging.SetMinimumLevel`).
- **Сообщить авторам Corvus.JsonSchema об ошибке `format: "regex"`.** Версия 5.7.9 при утверждении форматов считает `"\\."` (экранированную точку) неверным регулярным выражением, хотя для ECMA-262 оно верно, и сама же компилирует такой `pattern` без ошибок. Обойдено: метасхема проверяется без утверждения форматов.
- **Назначение дисциплин преподавателям (перспектива).** Сейчас любой преподаватель может создать РПД по любой дисциплине плана, если документа по ней ещё нет (этап 4, B3). В вузе дисциплины закрепляет кафедра: назначение «дисциплина — преподаватель» ограничило бы создание и список «Мои документы» закреплёнными дисциплинами.
- **Правила каталога без реализации** (на этапе 5 реализованы три, `hours_match_curriculum` — в этапе 5.2, B1.1, предупреждением): `all_indicators_covered` (каждый индикатор матрицы — хотя бы в одной теме), `unique_competence_codes`, `literature_main_count`, правила ФОС. Имена в схемах есть, при проверке пропускаются.
- **Колонка «Тип» в очереди «Согласование» (этап 6.1, C2).** В панели браузера шириной около 1000 px значение «РПД» переносится по буквам: длинный текст плана отнимает ширину у соседних колонок. Достаточно запретить перенос (`text-nowrap`) или задать колонке минимальную ширину; стоит проверить и списки «Проверка» и «Мои документы».
- **Потеря связи с сервером на странице документа (этап 6.1, C2).** Если сервер перестал отвечать, пока открыт документ с панелью печати, `PrintPanel.LoadAsync` не перехватывает `HttpRequestException` (только `AccessTokenNotAvailableException`): Blazor показывает полосу «Произошла необработанная ошибка» и пишет `crit` в консоль. Проверено остановкой сервера при открытой странице. Тот же приём стоит заложить в опрос колокольчика (C5): фоновый запрос без ответа не должен ломать страницу.
- **Автору — уведомление о ручном запуске согласования (этап 6.1, C3).** Когда документ ждал назначения согласующих и методист запустил согласование кнопкой, автор получил только прежнее «принят — ждёт назначения»: что ожидание кончилось, ему не сообщается (такого события в задании C3 нет). Можно добавить одно уведомление «согласование начато».
- **Заменённый согласующий и его уведомление (этап 6.1, C3).** При замене согласующего на идущем круге прежний остаётся с непрочитанным «ждёт вашего согласования», а документ из его очереди уже ушёл; переход по этому уведомлению даст ему 403. Если станет заметно — событие «вы больше не согласующий документа» или скрытие уведомлений о документе, к которому доступа нет.
- **Индекс ленты и очистка уведомлений (этап 6.1, C3).** Частичный индекс `notifications` — только по непрочитанным (счётчик); для ленты «последние уведомления получателя» подходящего индекса нет. На прототипе строк мало; при росте — индекс `(recipient_id, created_at DESC)` новой миграцией и очистка старых прочитанных уведомлений по сроку.
- **«Отмеченные мной» растёт без границы (этап 6.1, C4).** Строки круга согласованного документа остаются в `document_signatures` навсегда, поэтому список согласующего копит все его документы за всё время — без страниц и фильтров. На прототипе документов мало; при росте — показывать последние (например, 50) или добавить фильтр по статусу документа и срокам.
- **Стили без хеша в имени кэшируются браузером (этап 6.1, C5).** После пересборки колокольчик открылся без оформления: `RpdFos.Web.styles.css` (как и `css/app.css`) отдаётся без `Cache-Control`, браузер взял копию из кэша и не спросил сервер — то же замечание, что в записи C1. Помогла загрузка с `cache: 'reload'`. Достаточно отдавать эти два файла с `Cache-Control: no-cache`, как `index.html` (`ClientShell`), либо подключать их с версией в адресе.
- **Шум `HttpClient` в консоли клиента (этап 6.1, C5).** Опрос колокольчика (два запроса в минуту) пишет в консоль браузера по восемь информационных строк («Start processing HTTP request…», «Received HTTP response headers…»). Вместе с идеей про «Authorization failed» — одно решение: уровень Warning для клиента (`builder.Logging.SetMinimumLevel`).
- **Колонки «Тип» и «Статус» в «Проверке» и «Мои документы» (этап 6.1, C5).** Подтверждение идеи про «Согласование»: на ширине панели около 1000 px «РПД» переносится по буквам («РП/Д»), «Согласован» — «Согласов/ан», «На доработке» — «На доработк/е»; длинное название плана отнимает ширину у соседних колонок. Достаточно `text-nowrap` для этих колонок.
- **Предупреждение о ненайденном председателе УМК не называет направление (этап 6.1, C6).** Текст «Не найден подписант «Председатель учебно-методической комиссии по направлению подготовки» (правило …) — место напечатано пустой строкой» одинаков для любого направления. Тому, кто правит справочник, нужно знать, для какого направления нет председателя: достаточно передать направление плана в контекст резолвера и добавить в текст «для направления 15.05.01».
- **Один председатель УМК на несколько направлений (этап 6.1, C6).** Колонка `users.direction_id` (по заданию C6) связывает запись с одним направлением; если один человек возглавляет комиссию двух направлений, в справочнике нужны две записи на него. Если такое окажется обычным, вместо колонки нужна таблица связи «председатель — направление» (миграция и правка резолвера и страницы справочника).
- **Таблицы страницы документа на узком экране (этап 6.1, C7).** На ширине 375 px таблица листа согласования («Место / Согласующий / Отметка / Время / Комментарий») и таблица файлов панели печати шире экрана и раздвигают страницу (ширина документа 564 px): они не обёрнуты в `table-responsive`. Достаточно обёртки — после правки по замечанию C7 она прокручивается и переносит слова целиком.
